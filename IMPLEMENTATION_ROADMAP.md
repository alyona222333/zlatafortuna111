# Дорожня карта CRM

Усі зміни виконуються всередині цього проєкту. Після кожного етапу запускається production build, перевіряються API-маршрути та створюється резервний архів без секретів.

## Порядок реалізації

| Етап | Модулі | Результат |
|---|---|---|
| 1 | Товари, категорії, опції, імпорт, експорт | Повний каталог товарів із пошуком, фільтрами та збереженням у Supabase |
| 2 | Закупки, прийомка, повернення, переміщення, інвентаризація | Реальні складські рухи з журналом операцій |
| 3 | Дублі, кошик, статуси та джерела замовлень | Повний order pipeline для інтернет-магазину |
| 4 | Nova Poshta та Ukrposhta | Пошук, відправники, ТТН, трекінг та статуси доставки |
| 5 | Аналітика, транзакції, виписки, документи | Звіти, фільтри за періодами та експорт |
| 6 | Пошта, SMS, WhatsApp, Viber, телефонія | Канали комунікації з окремими статусами підключення |
| 7 | SaaS-тарифи та модулі | Включення функцій за тарифом, права доступу та ізоляція бізнесів |

## Статус на початок роботи

- Telegram: підключено.
- Nova Poshta: пошук міст і відділень працює.
- Supabase: використовується як база даних CRM.
- Booking, CRM-клієнти, POS, базовий склад, замовлення та фінанси: базові робочі екрани присутні.
- Ukrposhta: очікується договір та API-доступ.
- Телефонія: очікується вибір провайдера.

## Принципи

1. Не видаляти перспективні SaaS-модулі без необхідності.
2. Не показувати готовим те, що потребує зовнішнього ключа.
3. Для кожної інтеграції мати форму налаштування, перевірку підключення та зрозумілий статус.
4. Секрети зберігати в Netlify Environment Variables або в захищених полях CRM, а не в GitHub.
5. Не ламати дані існуючих бізнесів і не змінювати схему Supabase без міграції.
