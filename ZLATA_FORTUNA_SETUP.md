# Злата Фортуна Групп — что сделано и что дальше

## Что было исправлено/добавлено

### 1. Главный баг: сотрудники не могли зайти в систему
Проблема была не «где-то в ролях», а в двух местах, через которые проходят
абсолютно все страницы:
- `app/(dashboard)/layout.tsx`
- `lib/business.ts` → `getBusinessForOwner()` (её вызывают dashboard, pos, crm, inventory, booking)

Обе искали компанию только по `businesses.owner_id = текущий_пользователь`.
Значит, вообще никто, кроме владельца аккаунта, не мог попасть дальше — даже
если бы у сотрудника был логин. Права (RLS в базе) для сотрудников уже были
готовы (миграция `005_security_fixes.sql`), просто код никогда их не
использовал. Теперь оба места сначала проверяют владельца, а если это не он —
ищут сотрудника по `employees.user_id = текущий_пользователь` и берут его
компанию. Страница `Настройки` исправлена так же.

### 2. Вход для сотрудников (приглашения)
Раньше «Добавить сотрудника» в Настройках создавало только карточку в
календаре — без логина. Теперь:
- `supabase/migrations/037_employee_invites_and_roles.sql` — добавляет поля
  для одноразового приглашения.
- В Настройки → Сотрудники добавлена кнопка **«Запросити»** рядом с каждым
  сотрудником без логина — она создаёт ссылку-приглашение (действует 7 дней).
  Отправьте эту ссылку сотруднику (в мессенджер, почту — на своё усмотрение,
  автоматическая отправка письма не настроена).
- Сотрудник переходит по ссылке `/invite/xxxxx`, придумывает пароль и дальше
  входит на общей странице `/login` своим email и этим паролем.

### 3. Роли
Роль теперь выбирается из списка, а не вводится текстом:
Директор, HR, Менеджер з продажів, Маркетолог, IT, Аналітик, Співробітник.
Каждая роль видит только свой набор разделов в меню слева (файл
`lib/permissions.ts` — легко донастроить, кто что видит):

| Роль | Видит в меню |
|---|---|
| Владелец аккаунта / Директор | всё |
| HR | Панель, Настройки → Сотрудники, Аккаунт |
| Менеджер з продажів | Панель, Каса, Клієнти, Запис |
| Маркетолог | Панель, Клієнти, Аналітика |
| IT | Панель, Настройки → Сповіщення/Модулі/Аккаунт, Аналітика |
| Аналітик | Панель, Аналітика |
| Співробітник (за умовчанням) | Панель, Каса, Запис, Клієнти |

**Важно:** это ограничение только в интерфейсе (что показывается в меню).
Доступ к данным в базе (RLS) сейчас общий для всех сотрудников компании —
то есть технически через прямой запрос к API любой залогиненный сотрудник
может прочитать то же, что и остальные внутри своей компании. Если нужно,
чтобы, например, менеджер по продажам физически не мог увидеть финансовую
аналитику на уровне базы данных (а не только скрыть кнопку) — это отдельная,
более серьёзная доработка (нужно решить: в разрезе чего ограничивать —
по назначенным клиентам, по филиалу и т.д.).

### 4. Двуязычный интерфейс UA/RU
